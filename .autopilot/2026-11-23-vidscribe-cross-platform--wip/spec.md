# Спецификация: vidscribe для Mac и Windows

## Задача
Скилл vidscribe даёт агенту «посмотреть» видео: речь превращается в текст с таймкодами, а само видео остаётся, чтобы агент смотрел кадры через ffmpeg. Оригинал работает только на Mac с Apple Silicon. Пользователь сидит на Windows (видеокарта RTX 4070) и хочет ту же систему у себя, с распознаванием через ElevenLabs Scribe. Одна и та же версия должна работать и на Mac, и на Windows.

## Решение
Одна программа `vidscribe` на Python. Она ставится одинаково на обеих ОС через `uv tool install` и умеет распознавать речь тремя движками:
- **mlx** — как в оригинале, локально на Mac с Apple Silicon; там он по умолчанию.
- **scribe** — облачный ElevenLabs Scribe на любой ОС; на Windows он по умолчанию, если задан ключ.
- **whisper** — локальный faster-whisper на видеокарте NVIDIA или на процессоре, на любой ОС; ставится по желанию.

Всё остальное общее: скачивание, srt, видео для ffmpeg, предупреждения, очистка. Установщики — `install.sh` для Mac и `install.ps1` для Windows. Оба ставят программу и скилл в `~/.claude/skills/vidscribe`. Скилл и документация описывают обе ОС.

## Решения по реализации
- **Python-пакет `vidscribe`** (`pyproject.toml`, точка входа `vidscribe = vidscribe.cli:main`), ядро только на стандартной библиотеке. Почему: один язык для обеих ОС вместо bash. Ставится через `uv tool install`, uv сам приносит Python, на Mac не нужен системный python3.
- **yt-dlp — зависимость пакета**, вызывается как `python -m yt_dlp` из того же окружения. Почему: одна версия на обеих ОС, обновляется вместе с пакетом.
- **ffmpeg/ffprobe — внешние**, с PATH: brew на Mac, winget `Gyan.FFmpeg` на Windows.
- **Выбор движка**: сначала `-e`/`VIDSCRIBE_ENGINE`; иначе mlx, если это macOS arm64 и есть `mlx_audio.stt.generate`; иначе scribe, если задан `ELEVENLABS_API_KEY`; иначе whisper, если установлен faster-whisper; иначе ошибка со списком вариантов. Каждый запуск пишет `engine: <имя>` в stderr. ASSUMPTION: на Windows Scribe выше локального движка, потому что пользователь выбрал его.
- **Патч MLX** переносится из heredoc в отдельный файл пакета байт в байт и запускается интерпретатором mlx-audio, как раньше.
- **Scribe** — только stdlib (`urllib`, multipart вручную), `diarize=true`, `tag_audio_events=true`, `timestamps_granularity=word`. Субтитры собираются из слов: новая реплика при смене говорящего, паузе больше 1 с, конце предложения или длине больше 7 с. Если говорящих несколько, строка начинается с `[speaker_N]`; звуки пишутся как `(laughter)`.
- **whisper** — `faster-whisper` в extra `local`, CUDA-библиотеки в extra `cuda` (не для macOS); `vad_filter=True` против выдуманного текста в тишине; `-c` уходит в `hotwords`.
- **Python для установки** закреплён `--python 3.12`. Почему: для него точно есть готовые колёса ctranslate2 и nvidia.
- **ADR-0010** записывает, что ADR-0001 смягчён: облако — только по явному выбору (флаг или ключ), на Mac по умолчанию локально.
- **Тесты** — `unittest` из stdlib, без pytest; `tests/silent-video.sh` переносится в тест на Python.

## Вне рамок
| Требование | Почему не сейчас |
|---|---|
| Linux как цель | работает через scribe/whisper, но не проверяется и не заявлен как поддерживаемый |
| Intel Mac с локальным движком | MLX там нет; whisper на процессоре работает, но не проверяется |
| Повторы запросов к Scribe | платный запрос не повторяется молча; ошибка показывается |
| Новые замеры качества | цифры в README измерены на MLX; для Scribe и Whisper замеров нет — это сказано в README |
| Публикация форка на GitHub или PR в оригинал | внешнее действие — только по просьбе пользователя |

## Открытые места
- `ELEVENLABS_API_KEY` — пользователь задаёт сам; без него Scribe не проверить на настоящем API.
- Движок MLX не проверить на этом ПК — проверка на настоящем Mac остаётся пользователю.
